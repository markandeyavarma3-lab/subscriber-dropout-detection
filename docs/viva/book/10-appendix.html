APPENDIX AThe whole project on one page

ProblemPredict which subscribers of a music-streaming service cancel in the next 30 days, explain why, and run it as a trustworthy production system.
DataKKBox (WSDM Cup 2018, Kaggle): 31.3 GB, 6.77M subscribers. Cleaned into a Postgres event warehouse of 82.8M rows. 2.66M orphan rows dropped rather than invented.
No leakageFeatures from the 30 days before a cutoff; label from the 30 days after; windows never overlap; split by time (train Nov–Dec 2016, test Jan 2017).
ModelGradient boosting, 300 trees of depth 3. Test PR-AUC 0.073 (random 0.015: 4.8× better), ROC-AUC 0.835, recall 16.8% at threshold 0.05, calibration error 0.004.
Key findingOn real data ROC-AUC rose (0.674 → 0.835) while PR-AUC fell (0.345 → 0.073). So the gate uses PR-AUC.
AuditCalibrated; the cost audit prefers threshold 0.43 under placeholder costs; the fairness audit fails on the standard plan (reported and alerted).
RegistryMLflow. Live model = @champion. A challenger is promoted only if it beats the champion on PR-AUC, on the same data, by ≥ 0.005. Rollback = move the alias back.
ServingFastAPI with SHAP explanations that add up exactly to the prediction; a dashboard with counterfactual levers; a Kafka stream scorer, at-least-once, with a dead-letter queue.
MonitoringPrometheus (15 alert rules), Alertmanager (routing, inhibition), Grafana. PSI drift on real Feb 2017 data: stable, every feature under 0.06.
AutomationPrefect pipeline (ingest → drift → train and gate → report), idempotent. DVC + params.yaml. GitHub Actions: 7 jobs, 434 tests, image published to ghcr.io.
Deployment8 Docker services, make demo + 19-point make demo-check. Kubernetes manifests written, not deployed.
LimitationsModest model; fairness failure; placeholder costs; stricter churn label than Kaggle's; not on a public cloud.

APPENDIX DGlossary

A/B test
Real users are split between two versions and real outcomes compared.
Alias (MLflow)
A named pointer to a model version, such as @champion. Moving it promotes or rolls back.
Alertmanager
Groups, routes and suppresses alerts from Prometheus.
At-least-once delivery
Every message is processed one or more times; duplicates possible, loss not.
Baseline
The simplest reference a model must beat, such as random guessing.
Bias–variance trade-off
Too simple underfits (bias); too flexible overfits (variance).
Brier score
Mean squared error of predicted probabilities; lower is better.
Calibration
Whether predicted probabilities match observed frequencies.
Champion / challenger
The production model / the candidate evaluated against it.
Churn
A customer leaving. Here: an explicit cancellation within 30 days.
CI / CD
Continuous integration (build and test every change) / continuous delivery or deployment (release it).
Concept drift
The relationship between inputs and outcome changes.
Confusion matrix
Counts of true/false positives and negatives.
Container
An isolated, portable package of an application and its dependencies.
Counterfactual
"What would the model predict if this one input were different?"
Cutoff date
The "as of" date for a training example; features before it, the label after.
Data contract
Rules incoming data must satisfy before it's loaded.
Data drift
The distribution of inputs changes over time.
Data leakage
Training on information that wouldn't be available at prediction time.
Dead-letter queue
Where unprocessable messages go, with a reason, instead of crashing the consumer.
DVC
Data Version Control: versions data and pipeline stages.
ECE
Expected calibration error: the average gap between predicted and actual rates.
Event warehouse
A store of immutable, timestamped events, rebuildable as of any date.
F1
Harmonic mean of precision and recall.
Feature store
A system serving identical features to training and serving.
Four-fifths rule
A fairness convention: a group ratio below 0.8 is flagged.
Gauge / counter / histogram
Prometheus metric types: up-and-down value / only-increasing count / bucketed distribution.
Gradient boosting
Trees built one after another, each correcting the errors so far.
Grafana
Dashboards over Prometheus data.
HPA
HorizontalPodAutoscaler: Kubernetes adds or removes replicas to hold a target.
Idempotent
Running twice has the same effect as running once.
Inhibition
Suppressing alerts already explained by another alert.
Isotonic calibration
A monotonic mapping from raw scores to calibrated probabilities.
Kafka / Redpanda
A distributed log for event streams / a Kafka-compatible broker.
Liveness / readiness
Is the process up? / Can it serve traffic now?
Log-odds
ln(p ÷ (1 − p)); the scale boosting and SHAP work in.
MLflow
Experiment tracking and model registry.
MLOps
Practices for building, deploying and maintaining ML systems reliably.
Offset (Kafka)
A consumer's position in a topic partition.
Overfitting
Learning noise; good on training data, poor on new data.
Point-in-time correctness
Features use only what was known at the cutoff.
Poison message
A message that crashes a consumer every time it's read.
PR-AUC
Area under the precision–recall curve; random equals the positive rate.
Precision / recall
Of those flagged, share correct / of true positives, share flagged.
Prefect
Workflow orchestration: tasks, retries, schedules.
Prometheus
Pull-based metrics database with alert rules.
PSI
Population Stability Index: Σ (a − e) ln(a/e) over bins.
Reference profile
The training distribution, saved for drift comparisons.
ROC-AUC
Probability a random positive is ranked above a random negative.
Shadow scoring
A challenger scores live traffic silently; only the champion's answer is used.
SHAP
Game-theoretic feature contributions that add up to the prediction.
Temporal split
Train on earlier periods, test on later ones.
Threshold
The probability above which a subscriber is flagged.
Training–serving skew
Features computed differently in training and in production.
Volume (Docker)
Storage that outlives any container.
