Reading the drivers

Two things about this model surprise people. Both are real.

Auto-renew reads backwards
Enabling it raises predicted risk sharply — 0.0024 to 0.6037 on an otherwise identical subscriber. On KKBox's data an active auto-renew accompanies the short prepaid plans that churn most, so the model learned the association the data actually contains rather than the one intuition expects.
Two inputs do nothing
support_tickets_last_90d and payment_failures_last_6m move the prediction by exactly zero across their whole range. KKBox publishes no customer-service data and records a transaction only when money moved, so both columns are constant in training. They are kept on the form because the request schema requires them.
